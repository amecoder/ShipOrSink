# sos 단독 운영 보강 조사 (2026-11-27)

## 결론

`plugins/sos/standards/` 는 원래 저장소(비공개 dev-standards)의 커밋 `3d0eb76` 에서 **배포용 템플릿만** 복사한 것이다.
템플릿을 검사하고 유지하던 장치(테스트·CI·버전 갱신·관리 규칙)는 원래 저장소 루트에 있었기 때문에 따라오지 않았다.
원래 저장소는 더 이상 고치지 않는다(프리징). 따라서 sos 가 세 가지를 스스로 해야 한다.

1. **깔아 주기** — 사용자 프로젝트에 표준을 적용한다
2. **고치고 검사하기** — 표준을 바꿀 때 품질 기준이 실제로 지켜지는지 테스트한다
3. **최신으로 유지하기** — 도구 버전 핀을 갱신하고 릴리스한다

## 실측 기준선

원래 저장소의 bats 테스트(34개 파일, 414개)를 두 곳에서 같은 샌드박스로 돌렸다.

| 대상 | 통과 | 실패 |
|---|---|---|
| 비교군: 원래 저장소 `3d0eb76` | 353 | 61 |
| 이식본: sos 표준 폴더 + 같은 테스트 | 321 | 93 |

- 비교군 실패 61개는 두 곳에서 같다 — gradle·cargo 등 외부 다운로드가 샌드박스에서 막혀 생긴 환경 실패다.
  네트워크가 열린 환경에서 다시 재야 한다(아래 PR 2 판정 기준).
- 이식으로 새로 깨진 32개는 전부 **sos 에 없는 루트 운영 파일** 때문이다. 템플릿 자체 결함은 0개다.
  - Renovate 13 — `renovate.json`·`.github/workflows/renovate.yml` 없음
  - CI 대조 9 — 템플릿 도구 버전과 저장소 `ci.yml` 버전 일치 검사, 비교할 `ci.yml` 없음
  - 자기 적용 복사본 6 — `.github/`·`.claude/`·`.gitignore`·`AGENTS.md`·ruleset 없음
  - 도구 설치·린트 6 — `scripts/install-dev-tools.sh` 없음, shellcheck·actionlint 대상 없음
  - 문서 인용 1 — 품질 수치 인용이 원래 저장소 루트 README·AGENTS.md 에 있었음

## 발견 사항

### 1. 깔아 주기 — 지금 이미 틀린 안내

- `apply.sh` 머리말과 언어별 README 13개 파일, 92줄이 원래 저장소를 `~/.dev-standards` 로 clone 한 뒤
  `~/.dev-standards/...` 실행을 안내한다. 원래 저장소는 비공개라 공개 사용자는 받을 수 없다.
  실행 코드는 이 경로를 쓰지 않는다(도움말·안내문에만 등장) — 동작은 정상, 안내만 틀렸다.
- 사용 설명서가 없다. 원래 저장소 README(693줄)·QUICKSTART(167줄)에 있던 적용 수준 4단계(slim·standard·full·enterprise),
  언어별 적용, 품질 기준, 업데이트 방법이 sos README(61줄, 단계 스킬 소개)에 없다.
- 이름 표식: `.dev-standards.manifest`(적용 기록 파일)와 `dev-standards:issue-gate` 표식은 프로그램이 읽는 값이다 — **유지한다**
  (이미 표준을 적용한 프로젝트 호환). 주석·라벨 속 이름표 약 18곳은 sos 로 바꾼다.

### 2. 고치고 검사하기

- bats 34개 파일 + `helpers.bash` + 픽스처 → 저장소 루트 `tests/`. 헬퍼의 `REPO_ROOT` 를 `plugins/sos/standards` 로.
  플러그인 폴더 밖에 두어 설치본에 테스트가 포함되지 않게 한다.
- 검사 도구: `scripts/install-dev-tools.sh`, `scripts/local-ci.sh`, `.pre-commit-config.yaml`(10 훅, gitleaks 포함),
  `.shellcheckrc`, `.markdownlint.yaml`·`.markdownlintignore`, `.gitleaksignore`.
- CI: 원래 `ci.yml` 잡 8개(shellcheck·actionlint·python·bats·zizmor·renovate-config·markdownlint·apply-dry-run).
  공개 저장소는 Actions 무료라 원래 저장소의 "CI 는 로컬에서" 제약(비공개 무료 시간)이 적용되지 않는다.
- 관리 규칙: 원래 저장소 CLAUDE.md 「개발 규칙」 — 최신 정식판·배포 7일 규칙, `*_VERSION` + `# renovate:` 핀 규칙,
  워크플로 `uses:` 40자 SHA 핀, 규칙 프론트매터(`paths:`)·상시 로드 예산, 스킬 프론트매터 규격, AGENTS 32 KiB 한도.
  sos 에 CLAUDE.md·AGENTS.md 가 없다.
- 출처 주석: 예) `csharp-dotnet/templates/SonarLint.xml` 의 "검증: dev-standards tests/enforcement-csharp.bats" → sos 경로로.

### 3. 최신으로 유지하기

- Renovate 설정(꺼진 상태로 배치) + 주간 템플릿 최신성 검사(`template-freshness.yml`). 표준 안 `# renovate:` 핀 18곳.
- 릴리스 절차 없음: 플러그인 0.1.0. 표준을 바꾸고 버전을 올리지 않으면 사용자 설치본이 갱신되지 않는다. CHANGELOG 없음.
- 복사 시절 흔적: `standards/.source-commit`·`standards/.local-changes`, README 의 "dev-standards 템플릿의 복사본" 문장 → 정리.

### 4. 협업 장치 (2026-11-27 결정: 지금 같이 넣는다)

이슈 폼(AI Task·Bug·Feature), `labels.json`, ruleset, `CODEOWNERS`, PR 템플릿, PR 정책 검사(`pr-checks.yml` + `pr-policy.sh`),
보안 리뷰 게이트(`security-review.yml` — Semgrep·Gitleaks·Trivy), `ai-ready` 라벨 가드, 설정 반영 스크립트.
공개 저장소라 ruleset 이 동작한다(원래 저장소는 비공개 무료 플랜이라 403).

### 넣지 않는 것

- `.clinerules-*` 5개 — 예전 Cline 도구용. 참조 0곳. sos 로 옮기지 않고 원래 저장소 정리 때 삭제한다.
- 원래 저장소의 이력 문서(HANDOFF·CHANGELOG·research·plans) — 비공개 내용이 섞여 있다. 원래 저장소에 남긴다.
- 원래 저장소에 같이 있던 별도 엔진 모듈 — 자체 비공개 저장소로 분리된다. sos 범위 밖.

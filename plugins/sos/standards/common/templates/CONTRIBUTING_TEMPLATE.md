# Contributing

## Development Flow

1. Create a feature branch.
2. Write or update tests first for behavior changes.
3. Keep commits focused.
4. Run local verification before opening a PR.
5. Update docs, changelog, and handoff notes when behavior or project state changes.

## Branches

- Use feature branches.
- Do not commit directly to `main`.
- Prefer short-lived branches and small PRs.

## Commits

Use:

```text
<type>: <title>
```

Allowed types:

- `기능`
- `수정`
- `문서`
- `리팩터`
- `테스트`
- `빌드`
- `CI`

## Pull Requests

- Explain user impact.
- Include test results.
- Link related issues.
- Document rollout and rollback when operational risk exists.
- Request review from code owners.

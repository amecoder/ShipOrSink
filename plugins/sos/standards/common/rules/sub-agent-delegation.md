# Sub-agent Delegation Rules

언제 서브에이전트에 위임하고 언제 직접 처리할지에 대한 **수치 기준**. 정성적 룰("복잡하면 위임")은 주관적이라 컨텍스트 낭비를 유발한다.

## 1. 위임 결정 매트릭스

다음 조건 중 **2개 이상** 충족 시 서브에이전트에 위임:

| 조건 | 임계값 | 측정 방법 |
|------|--------|-----------|
| 컨텍스트 점유 예상 | ≥ 20% (컨텍스트 창 기준) 또는 팀이 정한 절대 상한 중 먼저 닿는 쪽 — 창이 커도 context rot 은 그대로다 | 도구 결과 + 파일 read 합산 추정 |
| 수정 대상 파일 수 | ≥ 5개 | 동일 작업에서 변경/생성 예상 파일 |
| 도메인 교차 | 2개 이상 | frontend + backend, infra + app, test + impl 등 |
| 같은 에러 반복 | 3회 이상 시도 실패 | 같은 에러 메시지 / 같은 도구 호출 |
| 작업 단계 수 | ≥ 6단계 | Plan Mode 결과의 단계 수 |
| 외부 라이브러리 조사 | 최신 API 검증 필요 | 학습 시점 이후 변경 가능성 |

**단일 조건만**:
- 컨텍스트 점유 ≥ 30% 또는 팀 절대 상한 도달 → 즉시 위임
- 같은 에러 3회 → 즉시 다른 모델 / debug-specialist에 위임

## 2. 위임하지 말아야 할 때 (Direct Path)

다음 작업은 메인 에이전트가 직접 처리:

- 단일 파일 수정 (< 100줄)
- 타이포 / 단순 리팩터링
- 파일 읽기 / grep / 코드 분석
- 사용자 질문 답변
- "빠르게 / 간단히" 같은 시간 제약 명시
- Plan Mode 결과가 3단계 이하

서브에이전트 spawn은 **2-5초 + 컨텍스트 복제 비용**이 든다. 짧은 작업은 직접이 더 효율적이다.

## 3. 에이전트 역할 분리 (Four-Eyes Principle)

| 역할 | 에이전트 | 컨텍스트 |
|------|----------|----------|
| Director | 메인 (최상위 추론 등급) | 사용자 의도, Plan, 결정 기록 |
| Worker | 서브에이전트 (중간 등급 또는 코딩 에이전트) | 단일 작업 수행 |
| Reviewer | 독립 에이전트 (작성과 다른 모델, 가능하면 다른 제공사) | **fresh context**, 결과만 받음 |

**금지**: 같은 세션에서 작성 → 검토 (편향 발생). 검토는 반드시 독립 컨텍스트.

## 4. 위임 시 전달 정보 표준

서브에이전트 spawn 시 다음을 명시 (필수):

1. **목표**: 한 문장으로 (왜)
2. **범위**: 수정 가능한 파일 경로 (3-10개)
3. **제약**: 변경 금지 / 의존성 / 호환성
4. **검증**: 성공 기준 (테스트 통과 / 린트 / 타입 체크)
5. **출력 형식**: diff / summary / structured / 코드 블록
6. **응답 분량**: "200단어 이내", "3단계 이하" 등

전달 안 하면 서브에이전트가 자율적으로 범위 확장 (scope creep).

## 5. 모델 라우팅 — 비용/지연 최적화

구체적인 모델 이름은 규칙에 적지 않는다 — 릴리스마다 바뀌므로 팀 설정(에이전트 정의의 `model:` · 환경 변수)에서 관리하고, 규칙은 **능력 등급**만 정한다.

| 작업 유형 | 모델 등급 | 근거 |
|-----------|-----------|------|
| Plan / 아키텍처 / 보안 결정 | 최상위 추론 등급 | 추론 깊이 |
| 코드 구현 / 리팩터 | 중간 등급 (코딩 성능과 비용의 균형) | 코드 능력 + 비용 |
| 단순 변환 / 포매팅 / 요약 | 경량 등급 | 비용 절감 |
| 대규모 리팩터 / 마이그레이션 | 쓰기 권한 샌드박스가 있는 코딩 에이전트 | workspace-write 권한 |
| 검증 (Reviewer) | 작성과 다른 모델 (가능하면 다른 제공사) | second opinion |
| 웹 검색 / 최신 문서 | 검색 도구가 붙은 모델 | 학습 시점 이후 데이터 |

비용 비율 가이드: **Plan 5% / 구현 70% / 단순작업 15% / 검증 10%**.

## 6. 병렬 vs 순차 실행

**병렬** (독립 작업):
- 여러 디렉토리 동시 탐색
- 독립 모듈 동시 구현
- 빌드 + 린트 + 테스트 동시 실행
- 여러 Eval 시나리오 동시 실행

**순차** (의존 작업):
- Plan → 구현 → 검증
- 구현 결과를 다음 단계 입력으로 사용
- 같은 파일 수정

병렬 가능 작업을 순차로 실행하면 시간/토큰 낭비. 단일 메시지에서 multiple tool calls.

## 7. 컨텍스트 누수 방지

서브에이전트 결과를 메인에 통합할 때:

- 전체 출력 X, **요약 + 결정사항**만
- 도구 호출 로그는 메인이 보지 않음 (이미 서브가 사용)
- 서브가 읽은 파일 목록은 트레이스용으로만, 메인에 재로드 X
- 충돌하는 결정은 사용자에게 에스컬레이트, 메인이 임의 판단 X

## 8. 검증 체크리스트 (위임 전)

- [ ] 위임 매트릭스 2개 이상 충족 확인
- [ ] 직접 처리가 더 빠르지 않은가 검토
- [ ] 전달 정보 6항목 모두 명시
- [ ] 모델 선택 근거가 비용/능력에 맞는가
- [ ] 결과 받은 후 메인 컨텍스트가 부풀지 않도록 요약 요청
- [ ] 검증 에이전트가 작성 에이전트와 다른 모델/세션인가

## 9. 안티패턴

- [ANTI] 모든 작업을 서브에이전트에 위임 (오버헤드 누적)
- [ANTI] 같은 에이전트에 작성 + 검토 시킴 (편향)
- [ANTI] 서브에이전트가 또 서브를 spawn (재귀, 추적 불가)
- [ANTI] 서브 결과를 그대로 사용자에게 전달 (메인이 책임 회피)
- [ANTI] 위임 시 범위 명시 안 함 (scope creep)
- [ANTI] 모든 서브에이전트에 같은 도구 셋 (최소 권한 원칙 위반)
